## Goals / Non-Goals

**Goals:**

- 8 個分頁完整編輯、伺服器端計算所有衍生數值、按確定才存檔並在離開前確認。
- 提供唯讀摘要給其他功能。

**Non-Goals:**

- 擲骰與技能檢定（dice-and-checks 負責）；本規格只記錄「本次成功使用過」勾選。
- 幕間成長檢定的自動擲骰。
- 其他規則系統。

## Decisions

### 採用角色數值板 8 分頁版本

以「角色數值板」頁為準，TV-8 舊版不實作。理由：欄位最完整、已有計算說明，且 TV-8 的能力值區塊是空框。TV-9 的列表外觀沿用。

### 衍生數值由伺服器計算

前端只送原始輸入（屬性初始與調整、技能加點、目前 HP 等），伺服器依 percentile-rules 計算後回傳整張卡。前端不自己算再寫回，避免不一致與竄改。編輯中畫面可先顯示前端試算值，但以伺服器回傳為準。

### 規則資料表化

技能清單（名稱、分組、基礎值）、職業清單（職業特徵公式、本職技能、信用範圍）存成資料檔，而不是寫死在頁面裡。日後換規則或修正數值只改資料檔。

### ruleData 結構

`Character.ruleData` 存 `{ version: 1, attributes: { STR: { initial, adjustment }, ... }, status: { hp, mp, san, luck, injury, insanity, insanitySymptoms }, skills: [{ id, occupation, interest, growth, usedThisSession, customName? }], weapons: [...], belongings, specialItems, backstory: {...}, record: {...}, identity: {...} }`；衍生數值不存，讀取時計算後一併回傳。`version` 供日後欄位遷移。

### 按確定才存檔

2026-11-27 決定，取代原本的「自動存檔防抖 2 秒」與「存檔」印章。不自動存檔，只有按右上角「確定新增」（剛新增的角色）或「確定修改」（原有角色，先跳「確定修改？」）才存檔，存完回到調查員總覽。有未存修改時顯示「尚未儲存」；沒按確定就要離開編輯分頁時跳「確定離開？」，確定後放棄修改，剛新增還沒確定的角色則一併刪除。確認視窗一律用共用元件 ConfirmDialog（#43）。

理由：自動存檔讓使用者不確定修改是否已生效，也無法放棄改到一半的內容；改成明確按確定，並在離開前確認，避免誤存與誤丟。已知限制：關掉分頁或重新整理不會跳確認。

多分頁同時開同一張卡時，以最後送達的為準並在另一頁提示「角色卡已在別處更新」。

### 分兩階段交付

**第一階段（12/19 前完成）**：調查員、身分、數值、技能一、技能二。

**第二階段（12/24 之後）**：裝備、背景、紀錄。

2026-11-21 決定。理由：擲骰與理智檢定只需要數值與技能，而 12/19 前要完成九成。第一階段時，8 個側邊分頁都顯示，第二階段的 3 頁先顯示「即將推出」。

### 計算函式放在共用資料夾

percentile-rules 的計算（困難／極限值、HP／MP／SAN 上限、體格、傷害加成、移動力、技能點數與最終值）都是純函式，放在共用型別資料夾。前端在假資料階段用它顯示試算值，後端用同一份計算後存檔。伺服器回傳的值仍是最終依據（見「衍生數值由伺服器計算」）。這樣前端可以先做，不必等後端。

## Implementation Contract

- **行為**：如兩份規格所述；所有 Example 表的數值由伺服器算出。
- **API**：`GET /api/characters`（自己的，支援 `q`、`page`）、`POST /api/characters`、`GET /api/characters/:id`（依 Field visibility 回完整或摘要）、`PATCH /api/characters/:id`（只收原始輸入，回傳含衍生數值的完整卡）、`DELETE /api/characters/:id`（使用中回 409）、`GET /api/characters/:id/summary`。
- **失敗模式**：超出範圍或點數超支回 400 並附欄位與訊息；非擁有者修改回 403。
- **驗收**：percentile-rules 每個 Example 表寫成伺服器單元測試；8 個分頁手動比對 char_0 至 char_7 設計圖。
- **範圍內**：列表、8 分頁編輯器、刪除、摘要、規則計算與資料檔。
- **範圍外**：擲骰、成長檢定、立繪以外的圖片管理、其他規則。

## Risks / Trade-offs

- [規則數值或表格抄自規則書而違反授權] → 技能與職業清單只放名稱、數值與團隊自己寫的說明，不複製規則書段落；上線前重新評估（見 guidelines 第 2 節）。
- [8 個分頁工作量大] → 建議前後端各一人；分頁可依任務順序分批交付。
- [Build 與傷害加成的表格超出 204 時] → 第一階段只支援到 204，超出時回 400「數值超出支援範圍」。
